## UC10 — บันทึกการยืมหนังสือ

| หัวข้อ | รายละเอียด |
|---|---|
| **Use Case ID** | UC10 |
| **ชื่อ** | บันทึกการยืมหนังสือ |
| **Actor หลัก** | LIBRARIAN |
| **Actor รอง** | MEMBER (ผู้มายืม) |
| **คำอธิบาย** | บรรณารักษ์บันทึกการยืมหนังสือให้สมาชิก โดยระบบตรวจสอบสิทธิ์การยืมและกำหนดวันครบกำหนดคืนอัตโนมัติ |
| **Trigger** | สมาชิกนำหนังสือมาที่เคาน์เตอร์ยืม |
| **Precondition** | 1. บรรณารักษ์เข้าสู่ระบบแล้ว<br>2. สมาชิกมีบัญชีในระบบ<br>3. ตัวเล่มมีอยู่จริงในระบบ |
| **Postcondition** | 1. เกิด Loan สถานะ ACTIVE พร้อม LoanItem ทุกเล่ม<br>2. ตัวเล่มทุกเล่มเปลี่ยนสถานะเป็น ON_LOAN<br>3. มีการบันทึก dueDate ตาม MemberTier |
| **Main Flow** | 1. บรรณารักษ์สแกนบัตรสมาชิก<br>2. ระบบแสดงข้อมูลสมาชิก ยอดค่าปรับค้าง และจำนวนที่ยืมอยู่<br>3. บรรณารักษ์สแกนบาร์โค้ดตัวเล่มทีละเล่ม<br>4. ระบบตรวจสอบสิทธิ์การยืมตามลำดับ BR-01 → BR-02 → BR-03 → BR-04 → BR-09<br>5. ระบบคำนวณ dueDate ตาม MemberTier (BR-05)<br>6. ระบบสร้าง Loan และ LoanItem บันทึกลงฐานข้อมูล<br>7. ระบบเปลี่ยนสถานะตัวเล่มเป็น ON_LOAN<br>8. ระบบแสดงใบยืมพร้อมรายการและวันครบกำหนด |
| **Alternative Flow** | **4a. สมาชิกสถานะ SUSPENDED (BR-01)** → ระบบตอบ 409 `MEMBER_SUSPENDED` และยุติ<br>**4b. ค่าปรับค้างเกิน 100 บาท (BR-02)** → ระบบตอบ 409 `UNPAID_FINE_EXCEEDED` และเสนอให้ชำระก่อน<br>**4c. ยืมเกินโควต้า (BR-03)** → ระบบตอบ 409 `LOAN_QUOTA_EXCEEDED`<br>**4d. ตัวเล่มไม่ว่าง (BR-04)** → ระบบตอบ 409 `COPY_NOT_AVAILABLE` และเสนอให้จองคิวแทน (ไปที่ UC04) |
| **Exception** | ฐานข้อมูลล้มเหลวระหว่างบันทึก → rollback ทั้ง transaction และตอบ 500 `INTERNAL_ERROR` |
| **Business Rules** | BR-01, BR-02, BR-03, BR-04, BR-05, BR-09 |
| **API ที่เกี่ยวข้อง** | `POST /api/v1/loans` |
| **Design Pattern** | Chain of Responsibility (`BorrowRule`) |

## UC11 — บันทึกการคืนหนังสือ

| หัวข้อ | รายละเอียด |
|---|---|
| **Use Case ID** | UC11 |
| **ชื่อ** | บันทึกการคืนหนังสือ |
| **Actor หลัก** | LIBRARIAN |
| **Actor รอง** | Reservation Queue |
| **คำอธิบาย** | บันทึกการคืนหนังสือ คำนวณค่าปรับหากคืนช้า และแจ้งเตือนสมาชิกที่จองคิวไว้ |
| **Trigger** | สมาชิกนำหนังสือในใบยืมมาคืนที่เคาน์เตอร์ |
| **Precondition** | รายการยืมมีสถานะ ACTIVE, OVERDUE หรือ LOST |
| **Postcondition** | 1. บันทึก returnedAt สำหรับรายการที่ยังไม่คืน; Loan เป็น RETURNED เมื่อคืนครบทุก item<br>2. หากไม่มีคิว ตัวเล่มเป็น AVAILABLE; หากมีคิว listener ผูกตัวเล่มกับ Reservation แรกเป็น READY และสถานะ copy เป็น RESERVED 48 ชั่วโมง<br>3. หากคืนช้า ระบบสร้าง Fine สถานะ UNPAID ตอนคืน<br>4. ผู้จองคิวแรกเป็นเจ้าของสิทธิ์ยืมตัวเล่มที่กันไว้ |
| **Main Flow** | 1. บรรณารักษ์เลือกใบยืมและกดบันทึกคืน<br>2. ระบบโหลดรายการ LoanItem ที่ยังไม่คืนในใบยืมนั้น<br>3. ระบบตรวจ transition ผ่าน State Pattern และบันทึกวันคืนของรายการที่ยังไม่คืน<br>4. หากรายการเกินกำหนด ระบบเลือก FineCalculationStrategy ตาม MemberTier และบันทึกค่าปรับตอนคืน (BR-07)<br>5. ระบบเปลี่ยนตัวเล่มเป็น AVAILABLE และ publish `BookReturnedEvent`<br>6. หลัง commit listener ผูกตัวเล่มกับ Reservation คิวแรก เปลี่ยนเป็น READY และกำหนดเวลารับ 48 ชั่วโมง (BR-10)<br>7. ระบบแสดงผลคืนและค่าปรับ; การแจ้งเตือนภายนอกยังไม่ได้เชื่อมอีเมลหรือ SMS |
| **Alternative Flow** | **3a. ใบยืมหรือรายการคืนแล้ว** → ระบบปฏิเสธการคืนซ้ำ<br>**4a. คืนตรงเวลา** → ไม่สร้าง Fine<br>**6a. ไม่มีคิวจอง** → ตัวเล่มคงเป็น AVAILABLE<br>**6b. เจ้าของคิวมายืม** → ระบบยอมรับตัวเล่ม RESERVED และเปลี่ยน Reservation เป็น FULFILLED<br>**6c. ยกเลิก/หมดเวลา 48 ชั่วโมง** → ปล่อยตัวเล่มและส่ง event ให้คิว WAITING ถัดไป |
| **Business Rules** | BR-07, BR-08, BR-10 |
| **API ที่เกี่ยวข้อง** | `PATCH /api/v1/loans/{id}/return` |
| **Design Pattern** | State, Strategy, Observer |

## UC12 — ต่ออายุการยืม

| หัวข้อ | รายละเอียด |
|---|---|
| **Use Case ID** | UC12 |
| **ชื่อ** | ต่ออายุการยืม |
| **Actor หลัก** | LIBRARIAN หรือ ADMIN |
| **คำอธิบาย** | ขยายกำหนดคืนของรายการที่ยังไม่คืนในใบยืม โดยเพิ่มครั้งต่ออายุและขยายกำหนดคืน 7 วัน |
| **Precondition** | ใบยืมมีรายการที่ยังไม่คืน และสถานะรองรับการต่ออายุ |
| **Main Flow** | 1. เจ้าหน้าที่เลือกใบยืมและกดต่ออายุ<br>2. ระบบปฏิเสธหากมีคิว WAITING สำหรับชื่อหนังสือในใบยืม<br>3. State ของใบยืมตรวจว่าสถานะอนุญาตต่ออายุ<br>4. ระบบขยายกำหนดคืน 7 วันและเพิ่ม renewCount ให้รายการที่ยังไม่คืน |
| **Alternative Flow** | ต่ออายุครบ 2 ครั้ง, ใบยืม OVERDUE/LOST/RETURNED หรือมีคิว WAITING → ระบบตอบข้อผิดพลาดทางธุรกิจและไม่บันทึกการต่ออายุ |
| **API ที่เกี่ยวข้อง** | `PATCH /api/v1/loans/{id}/renew` |
| **Design Pattern** | State; ตรวจคิวจองใน service ก่อน transition |

## UC04 — จองหนังสือ

| หัวข้อ | รายละเอียด |
|---|---|
| **Use Case ID** | UC04 |
| **ชื่อ** | จองหนังสือ |
| **Actor หลัก** | MEMBER |
| **คำอธิบาย** | สมาชิกจองคิวหนังสือที่ตัวเล่มถูกยืมออกไปหมดแล้ว เพื่อรอรับเมื่อมีผู้คืน |
| **Trigger** | สมาชิกกดปุ่ม "จองคิว" ในหน้ารายละเอียดหนังสือ |
| **Precondition** | 1. สมาชิกเข้าสู่ระบบแล้ว<br>2. สมาชิกยังไม่มีการจองที่ยัง active ของหนังสือเล่มนี้<br>3. สมาชิกไม่ได้กำลังยืมชื่อหนังสือนี้อยู่<br>4. สมาชิกอ่านและยอมรับกฎการยืมหรือจองก่อนส่งคำขอ |
| **Postcondition** | เกิด Reservation สถานะ WAITING พร้อมลำดับคิว |
| **Main Flow** | 1. สมาชิกค้นหาและเปิดรายละเอียดหนังสือ (UC02, UC03)<br>2. ระบบแสดงจำนวนตัวเล่มที่ว่าง = 0 พร้อมปุ่มจองคิวและทางอ่านกฎ<br>3. สมาชิกอ่านและติ๊กยอมรับกฎการใช้บริการ แล้วกดจองคิว<br>4. ระบบตรวจสอบการยอมรับกฎ, การจองซ้ำ และรายการยืมที่ยังไม่คืน (BR-09)<br>5. ระบบสร้าง Reservation สถานะ WAITING<br>6. ระบบแสดงลำดับคิวและเพิ่มรายการไว้ในประวัติการจองของสมาชิก |
| **Alternative Flow** | **4a. สมาชิกไม่ยอมรับกฎ** → ระบบไม่ส่งคำขอจากหน้าเว็บ และ API ตอบ 400 หากส่งคำขอโดยตรง<br>**4b. มีการจองซ้ำ** → ระบบตอบ 409 `DUPLICATE_RESERVATION`<br>**4c. สมาชิกกำลังยืมชื่อหนังสือนี้อยู่** → ระบบตอบ 409 `BOOK_ALREADY_ON_LOAN`<br>**2a. ยังมีตัวเล่มว่าง** → ซ่อนปุ่มจองและแสดงปุ่มยืมเอง (UC20)<br>**3a. ผู้ใช้ไม่ได้เข้าสู่ระบบ** → ขอให้เข้าสู่ระบบก่อนจอง |
| **Business Rules** | BR-09, BR-10 |
| **API ที่เกี่ยวข้อง** | `POST /api/v1/reservations/self`, `GET /api/v1/reservations/self`, `DELETE /api/v1/reservations/{id}` |

## UC02 — ค้นหาหนังสือ

| หัวข้อ | รายละเอียด |
|---|---|
| **Use Case ID** | UC02 |
| **ชื่อ** | ค้นหาหนังสือ |
| **Actor หลัก** | MEMBER (และผู้ใช้ทั่วไปที่ยังไม่เข้าสู่ระบบ) |
| **คำอธิบาย** | ค้นหาหนังสือจากชื่อเรื่อง ผู้แต่ง หรือหมวดหมู่ พร้อมแบ่งหน้าและเรียงลำดับผลลัพธ์ |
| **Precondition** | ไม่มี (เป็น endpoint สาธารณะ) |
| **Postcondition** | ระบบแสดงผลลัพธ์พร้อมจำนวนตัวเล่มที่ว่างของแต่ละเล่ม |
| **Main Flow** | 1. ผู้ใช้กรอกคำค้นและ/หรือเลือกหมวดหมู่<br>2. ผู้ใช้เลือกจำนวนรายการต่อหน้าและเกณฑ์การเรียง<br>3. ระบบ query ฐานข้อมูลพร้อม LIMIT/OFFSET<br>4. ระบบคืนผลลัพธ์แบบ Page พร้อม metadata (totalElements, totalPages)<br>5. ผู้ใช้เลื่อนดูหน้าถัดไป |
| **Alternative Flow** | **3a. ไม่พบผลลัพธ์** → ระบบตอบ 200 พร้อม content ว่าง ไม่ใช่ 404 |
| **API ที่เกี่ยวข้อง** | `GET /api/v1/books?keyword=&categoryId=&page=&size=&sort=` |

## UC20 — สมาชิกยืมหนังสือจากแคตตาล็อก

| หัวข้อ | รายละเอียด |
|---|---|
| **Use Case ID** | UC20 |
| **ชื่อ** | ยืมหนังสือด้วยตนเอง |
| **Actor หลัก** | MEMBER |
| **คำอธิบาย** | สมาชิกเลือกหนังสือที่มีตัวเล่มว่างจากหน้าแคตตาล็อก แล้วส่งคำขอยืมโดยไม่ต้องทราบ barcode หรือ member ID |
| **Trigger** | สมาชิกกด “ยืมหนังสือเล่มนี้” ในหน้ารายละเอียดหนังสือ |
| **Precondition** | 1. สมาชิกเข้าสู่ระบบแล้ว 2. หนังสือมีตัวเล่มสถานะ `AVAILABLE` อย่างน้อยหนึ่งเล่ม 3. สมาชิกอ่านและยอมรับกฎการยืมก่อนส่งคำขอ |
| **Postcondition** | สร้าง Loan สถานะ `ACTIVE`, เพิ่ม LoanItem, เปลี่ยนตัวเล่มที่เลือกเป็น `ON_LOAN`, แสดงรหัสใบยืมและวันครบกำหนด |
| **Main Flow** | 1. สมาชิกอ่านกฎในหน้า Rules หรือรายละเอียดหนังสือ แล้วติ๊กยอมรับ 2. Browser ส่ง `bookId` และ `termsAccepted: true` พร้อม Bearer JWT 3. Backend ระบุสมาชิกจาก subject ใน JWT 4. ระบบล็อกแถวตัวเล่มว่างและเลือก barcode แรก 5. ระบบตรวจ BR-01..BR-04 และ BR-09 ผ่าน BorrowRule chain 6. ระบบคำนวณ dueDate ตาม MemberTier 7. ระบบบันทึก Loan/LoanItem และเปลี่ยนสถานะ copy 8. Browser แสดงผลสำเร็จและลิงก์ไปประวัติการยืม |
| **Alternative Flow** | **2a. ไม่ได้เข้าสู่ระบบ** → ขอให้เข้าสู่ระบบก่อนยืม<br>**2b. ไม่ยอมรับกฎ** → ปุ่มยืมยังใช้งานไม่ได้ และ API ตอบ 400 หากส่งคำขอโดยตรง<br>**4a. ไม่มีตัวเล่มว่าง** → หน้าเว็บแสดงทางเลือกจองคิว (UC04); หากตัวเล่มถูกยืมระหว่างเปิดหน้า ระบบตอบ 409 `COPY_NOT_AVAILABLE`<br>**5a. สมาชิกติดระงับ ค่าปรับ, โควต้า หรือมีรายการยืมชื่อเดียวกันที่ยังไม่คืน** → ตอบ 409 พร้อม error code ที่ตรงกับกฎ |
| **Exception** | หากบันทึกฐานข้อมูลผิดพลาด transaction จะ rollback ทั้ง Loan และสถานะตัวเล่ม |
| **Business Rules** | BR-01, BR-02, BR-03, BR-04, BR-05, BR-09 |
| **API ที่เกี่ยวข้อง** | `POST /api/v1/loans/self` |
| **Design Pattern** | Chain of Responsibility (`BorrowRule`) |
